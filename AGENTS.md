# Tsukumo project rules

Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) first. The shape: **TsukumoKit**, a Swift package shared by everything; the macOS 26 **Tsukumo Mac app** in `apps/macos` (Tsukumo's Dock, `com.zlichtman.tsukumo.mac`: the side dock of your bots with all its customization, from the menu bar, and nothing else; MacSpaces is a separate app); and the **Tsukumo iPhone app** in `apps/ios`, on its own App Store record. The code of the old apps as they stood on September 30, 2026 (Tsukumo 77 for Mac in `legacy/macos/`, and KemoSabe iPhone build 69 with its Apple Watch app in `legacy/ios/`, which also holds the sources the old Mac app compiled) is kept in `legacy/` for reference only.

1. Every finished change goes to TestFlight: build, test, bump the build number, upload, and report Apple's real status.
2. The iPhone app's version stays 1.0.0 and its build number goes up (`apps/ios/project.yml`; `scripts/upload-testflight.sh <build>` bumps it, archives, and uploads); tag `v1.0.0` only on the real public release, and never move a tag. The Mac app (Tsukumo's Dock, `apps/macos`) is version 2.<NN>, like MacSpaces' 2.x: build 200 is version 2.00, build 201 is 2.01 (`scripts/release-mac.sh <build>` sets `CURRENT_PROJECT_VERSION` and `MARKETING_VERSION` in `apps/macos/project.yml`). The old coding harness ended at 1.80.
3. Uploads use the App Store Connect API key, never a password typed for the owner.
4. The Mac app keeps bundle ID `com.zlichtman.tsukumo.mac` (team 28LJG7MXT3, hardened runtime, not sandboxed), installs over `/Applications/Tsukumo.app`, and ships as one notarized Developer ID build through Homebrew (`zlichtman/tap/tsukumo`) and the owner's website, only when the owner approves a release.
5. Agent rules live in AGENTS.md; never create CLAUDE.md.
6. Keep the UI guide (`design/UI-GUIDE.md`) and the code in step.
7. Fix foundations (data integrity, migration, deletion, test isolation) before new features.
8. Stock theme names never use another company's name.
9. iPhone and Mac settings come from one catalog, with the same groups, names, and order.
10. Models is one page; Account covers identity and sign-in; there's no separate Profile page.
11. Avoid redundant controls: one Settings window on the Mac, and no choice of where the bots live: on a Mac, Tsukumo is the side dock. Tsukumo has no KemoSabe mode: KemoSabe is its local bot.
12. Mac builds are published only when the owner approves, and only by `scripts/release-mac.sh <build>`: it runs TsukumoKit's tests, builds the notarized Developer ID app from `apps/macos` (`TSUKUMO_CAPABILITIES=Local` until a Developer ID profile with iCloud and Sign in with Apple is installed) and its DMG, puts it on the owner's website (the Portfolio site's `public/downloads/Tsukumo-<version>.dmg`, for example `Tsukumo-2.00.dmg`, with `/downloads/Tsukumo.dmg` redirecting to it and `tsukumo.json` as the feed the cask's livecheck reads), deploys with the Vercel CLI, and updates the cask in `zlichtman/homebrew-tap` (`version "2.<NN>"`, `uninstall quit: "com.zlichtman.tsukumo.mac"`, livecheck from `tsukumo.json`, and no `auto_updates`, since this app has no updater of its own and `brew upgrade` updates it). Try it with `--dry-run` first. No `tsukumo-b<N>` releases and never a public GitHub release; the tap holds casks only.
13. Keep the documentation consolidated and current with every change, in the same commit or merge, never later. `README.md` is public only, written for someone discovering the project: the story, the problem it solves, visuals, and how to get and use it. It never holds build numbers, status, in-progress notes, known issues, or developer instructions; change it only when what a user can get or do changes. `DEVELOPMENT.md` holds status, build and release steps, the code map, and known issues. The design doc for the area touched and the build's release record in `docs/releases/` are updated too. One current doc per topic; superseded docs are removed, not left beside the new ones.
14. User-facing text never shortens KemoSabe to "Kemo" (it sounds like "chemo"): say KemoSabe, or the companion's own name when the person named it. A person's agent is "<Name>'s secure assistant". This covers the apps, notices, demos, the website, README, and release notes; code identifiers may keep "Kemo".
