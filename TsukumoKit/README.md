# TsukumoKit

The Swift package the Tsukumo iPhone app (`apps/ios`) is built on. The design is [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

- **Platforms:** iOS 26 and macOS 15. macOS stays a build platform so the modules compile on a Mac too; the app is iPhone only. Anything that needs macOS 26 or iOS 26 (Foundation Models) is marked `@available`.
- **Dependencies:** none outside Apple's SDKs. The MLX models (Whisper and Kokoro) are a separate package beside it, `MLXVoice/` (`TsukumoMLXVoice`), which the app adds; provenance in [VOICE-NOTICE.md](VOICE-NOTICE.md).
- **Concurrency:** Swift 6 language mode with strict concurrency.

## Modules

Dependencies point down this list only.

| Module | What it does |
|---|---|
| `TsukumoCore` | The shared vocabulary. `BotSpec` (name, engine, model, effort, role, look, context scope, permissions, instructions, origin; `normalized()` keeps KemoSabe standard, with only its companion palette and figure), the owner's bots (`BotLineup`: KemoSabe, then the owner's bots in their order; `BotOrigin`, `ServiceID`, `ServiceConnections`), `LineupAliases` and `LineupMigration` (what the old fixed lineup retired, and an old chat rewritten through it), `BotLook` (KemoSabe's palette and figure, a bot's character and its still picture) and `KemoSabeLook` (the switch between its two-tone look and its cloud), `BotPalette` (KemoSabe's companion palettes and the map from its old accent colors), `DefaultModel`, `ChatThread`, `Message` with its `Part`s (text, status, artifact references, KemoSabe's question and answer cards), tag-to-send `Routing` (chips, `@name`, a unique first word, the bot last spoken to), `PrivacyLevel`, `ArtifactRef`, and the effort catalog. Saved data round-trips, and parts written by a newer build are kept as written. |
| `TsukumoPolicy` | One pure decision: may this item go to this recipient? `ContextPolicy.evaluate` works only from type labels (an item kind with its floor, plus a level), grants (always, once, expiry), and an optional bot ceiling. A classifier can only raise a label. |
| `TsukumoContext` | The never-ending context. `ArtifactStore` is an SQLite store of versioned artifacts. A revision is written once, never changed, and a database trigger refuses any change. Reads are pinned to a revision and its SHA-256, return exact lines, and fail rather than truncate. Labels flow down lineage. Revoking an artifact erases its content and everything derived from it. `ContextSelection` builds a turn's working set: pinned constraints first, then a chooser's bounded reads, and when the chooser abstains, everything authorized that fits. |
| `TsukumoGate` | KemoSabe. What it may read: `SourceLibrary`, a catalog grouped by kind with each source's state and level, as many picked files and connected accounts as the owner likes, saved as `sources.json`; the sources themselves (`RemindersSource`, `ContactsSource`, `SharedMessagesSource`, `PhotosSource`, `FolderSource`, `LocationSource`, `MusicSource`, and `ConnectorSource` over a small MCP client, `MCPClient`; Calendar isn't offered, and `SourceKind.calendar` stays only so older settings decode), the system's permissions (`SystemSourceAuthorizer`), and stand-ins for UI tests. `Gate.ask` handles consent (Allow always, Allow once, Don't allow with a quiet period) and per-bot limits. It checks the policy before any read, so Device only, Secret, and anything above the bot's ceiling are never read for an agent. Each Sensitive item gets its own share card. Answers leave through single-use `DisclosureEnvelope`s and are kept as `personalAnswer` artifacts. `GateJournal` records what was sent, and only counts of what was left out. Extraction runs on Apple's on-device model (`AppleExtractionModel`), with `FixtureExtractionModel` for tests and the demo. |
| `TsukumoGateway` | The KemoSabe gateway, built for the Tsukumo Mac app (no longer in this repo) and kept for bringing the gateway to the iPhone; the iPhone app doesn't use it yet. Agents elsewhere ask KemoSabe through typed tools (`GatewayTools`: free/busy, contact lookup, ask, and, once the owner turns them on, list, share a file, a message excerpt, or a photo, and deliver into the Inbox) over MCP's Streamable HTTP on 127.0.0.1 (`GatewayServer`, Network.framework), with its own OAuth 2.1 authorization server (`GatewayAuthorization`: metadata, dynamic registration, PKCE S256, rotating refresh tokens, the owner's sign-in queue). Plain code decides: standing grants per caller (`GatewayGrant`), the owner's cards (`GatewayDesk`: never the caller's words, deduplicated, bounded), and the disclosure ledger (`DisclosureLedger`: facts, units, budgets, and risk flags, never content). Its public address is the Tsukumo relay's client (`RelayConnection`: one outbound WebSocket, the device's P-256 key in the Keychain or Secure Enclave, relayed requests into the same `GatewayServer.respond(to:via:)`; the wire format alone in `RelayEnvelope`). `KemoSabeGateway` puts it together for an app. |
| `TsukumoSystemOne` | Decisions with per-kind thresholds and abstention. `SystemOne.decide` asks the local provider first (Laya, with the owner's personal layer), then hosted services in order, and each hosted call passes the policy first; each provider is raced against the decision's deadline. `SystemOneAPIProvider` speaks the System One API for Cloudflare Clef-flash and Clef (Workers AI's envelope), Jev, or a custom endpoint, and `SystemOneSettings` keeps them in the order they're asked, each agreed to for its host. `DecisionJournal` never holds the request's words. `SystemOne.route` picks the bot for an untagged message, falling back to the bot last spoken to. `SystemOneContextChooser` is `selectContext`. |
| `TsukumoEngines` | One `Engine` protocol that streams a turn: text, tool calls and results, approvals, and the reply. `APIEngine` speaks Claude's Messages API and OpenAI-compatible chat/completions, with keys kept in the Keychain. `OnDeviceEngine` runs Apple's on-device model (KemoSabe the bot). Every engine gets `read_reference` and `ask_kemosabe` through `TurnTools`. `CodingAgentEngine` (macOS only, left from the Mac app and unused on iPhone) runs a turn on the owner's own coding CLI (`ClaudeCodeBackend`, `CodexBackend`, `ACPBackend`, found by `CodingAgentCatalog`). |
| `TsukumoSync` | `SyncEngine` syncs labeled items through a `CloudDatabase`, checking each against the policy for iCloud. Device only, Secret, KemoSabe's answers, and personal-source items never leave. `InMemoryCloudDatabase` is for tests. `CKCloudDatabase` is the CloudKit adapter. `LibraryMapping` and `LibrarySyncController` keep bots, chats, the default model, and connections (never keys) in step across the owner's devices: chats merge by message, deletes are tombstones, Device only chats and KemoSabe's shared answers never leave, and the status line says why sync is off. `CloudCapability` turns it on only in a build signed with the iCloud capability. |
| `TsukumoVoice` | Listening and speaking, always the best the device can run, with no model menus (the old KemoSabe app's evaluated stack). `VoiceHub` holds the two pinned downloads (`VoiceModelStore`: Whisper large-v3-turbo 4-bit and Kokoro-82M, checked file by file against size and SHA-256, after one consent), the owner's settings (spoken replies, pace), Settings' status lines, a turn of listening (`VoiceListener`: Apple's on-device recognizer for the live words, `EndOfSpeech` to end a tap when you stop talking, then Whisper's reading of the same audio when it can run, by `WhisperTranscription`'s rules), and a reply spoken in the bot's voice while it streams in (`ReplySpeech`, `SpeechQueue`, the Apple voice taking over if Kokoro fails). Each bot's voice is one of Kokoro's nine (`KokoroVoices.voice(for:)`), with Apple's closest voice standing in. `NeuralVoiceRuntime` is what MLXVoice fills. `ScriptedSpeechCapture` stands in for the microphone in tests and pictures. |
| `TsukumoUI` | The chat as on the website demo (`ChatSession`, `ChatScreen`, KemoSabe's card with its consent and share cards, the composer with bot chips, `@name`, and the model chip, whose `ModelSheet` sets a bot's model, power, and speed through the app's `ComposerActions`), the design system every screen is built from (`DesignSystem.swift`: the theme's surfaces, `TsukumoMetrics`, `PressableButtonStyle`, `ControlCircle`, `TsukumoSegmented`, `TsukumoEmptyState`, and the `tsukumoScreen`, `tsukumoRows`, `tsukumoSheet`, and `fittedSheet` modifiers; the power slider in `PowerControls.swift`), KemoSabe in its look and mood (`KemoSabeFigure`, `KemoSabeFace`, `TwoTonePainter`; the cloud in its palette is `CompanionArt`), the services' marks (`ServiceMarkView`), the bots' settings (`BotSettingsSheet`: `KemoSabeEditor`, KemoSabe's character, palette grid, and voice, or `BotEditor`, a bot's brain, details, character, voice, context, and permissions; a bot's voice is `VoicePicker`; the composer's microphone is `ComposerMicButton` and `ListeningStrip`, and `ChatSession.say` sends what was said and speaks the reply), the bots' characters (`BotCharacterView`, `BotCharacterPicker`: Tsukumo's own characters, drawn from their sheets by `CodexPetView`, a pet's still picture, or a service's mark; reading the owner's Codex pets is macOS only), Settings' one catalog (`SettingsCatalog`: its pages, Models' tabs, and what search finds), the first run (`OnboardingFlow` over an app's `OnboardingHost`), the account (`AccountStore`, Sign in with Apple, `AccountSummary` with its sign-in hero or the name, initials, and sync's pill, and `SyncFacts`), API connections (`ConnectionRecord`, `ModelCatalog`), Activity (`ActivityFeed`), and `DemoFixture`, which plays the website demo through the real Gate. The kit fills the chat's seams through `EngineRunner`, `GateAnswerer`, and `SystemOneRouter`. |

## Building

From this folder:

```sh
swift build --scratch-path /tmp/tsukumokit-build
```

Pass a scratch path outside iCloud Drive to keep build products out of it. `swift build --package-path MLXVoice --scratch-path /tmp/tsukumo-mlxvoice-build` builds the MLX package (it fetches MLX Swift and the Hugging Face packages the first time). There's no test suite (October 8, 2026); the app that uses these modules is in `apps/ios` (see DEVELOPMENT.md).
