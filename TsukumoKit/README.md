# TsukumoKit

The Swift package every Tsukumo surface shares: the iPhone app (`apps/ios`) and the Mac app (`apps/macos`, the side dock). The design is [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

- **Platforms:** iOS 26 and macOS 15. Anything that needs macOS 26 or iOS 26 (Foundation Models) is marked `@available`.
- **Dependencies:** none outside Apple's SDKs (TsukumoMuse ports Meta's Muse Gadget SDK in Swift; provenance in [MUSE-NOTICE.md](MUSE-NOTICE.md)). The MLX models (Whisper and Kokoro) are a separate package beside it, `MLXVoice/` (`TsukumoMLXVoice`), which the apps add; provenance in [VOICE-NOTICE.md](VOICE-NOTICE.md).
- **Concurrency:** Swift 6 language mode with strict concurrency.

## Modules

Dependencies point down this list only.

| Module | What it does |
|---|---|
| `TsukumoCore` | The shared vocabulary. `BotSpec` (name, engine, model, effort, role, look, context scope, permissions; `normalized()` keeps KemoSabe standard, with only its companion palette), the fixed lineup (`ServiceID`, `ServiceConnections`, `ServiceLineup`: KemoSabe and one bot per connected service), `LineupMigration` (folding custom bots into their service, archiving the rest, the notice), `BotLook` (KemoSabe's palette) and `KemoSabeLook` (the switch between its two-tone look and its cloud), `BotPalette` (KemoSabe's companion palettes and the map from its old accent colors), `DefaultModel`, `ChatThread`, `Message` with its `Part`s (text, status, artifact references, KemoSabe's question and answer cards), tag-to-send `Routing` (chips, `@name`, a unique first word, the bot last spoken to), `PrivacyLevel`, `ArtifactRef`, and the effort catalog. Saved data round-trips, and parts written by a newer build are kept as written. |
| `TsukumoPolicy` | One pure decision: may this item go to this recipient? `ContextPolicy.evaluate` works only from type labels (an item kind with its floor, plus a level), grants (always, once, expiry), and an optional bot ceiling. A classifier can only raise a label. |
| `TsukumoContext` | The never-ending context. `ArtifactStore` is an SQLite store of versioned artifacts. A revision is written once, never changed, and a database trigger refuses any change. Reads are pinned to a revision and its SHA-256, return exact lines, and fail rather than truncate. Labels flow down lineage. Revoking an artifact erases its content and everything derived from it. `ContextSelection` builds a turn's working set: pinned constraints first, then a chooser's bounded reads, and when the chooser abstains, everything authorized that fits. |
| `TsukumoGate` | KemoSabe. What it may read, for both apps: `SourceLibrary`, a catalog grouped by kind with each source's state and level, as many picked files and connected accounts as the owner likes, saved as `sources.json`; the sources themselves (`CalendarSource`, `RemindersSource`, `ContactsSource`, `MacMessagesSource` and `SharedMessagesSource`, `PhotosSource`, `FolderSource`, `LocationSource`, `MusicSource`, and `ConnectorSource` over a small MCP client, `MCPClient`), the system's permissions (`SystemSourceAuthorizer`), and stand-ins for UI tests. `Gate.ask` handles consent (Allow always, Allow once, Don't allow with a quiet period) and per-bot limits. It checks the policy before any read, so Device only, Secret, and anything above the bot's ceiling are never read for an agent. Each Sensitive item gets its own share card. Answers leave through single-use `DisclosureEnvelope`s and are kept as `personalAnswer` artifacts. `GateJournal` records what was sent, and only counts of what was left out. Extraction runs on Apple's on-device model (`AppleExtractionModel`), with `FixtureExtractionModel` for tests and the demo. |
| `TsukumoGateway` | The KemoSabe gateway (macOS): agents elsewhere ask KemoSabe through typed tools (`GatewayTools`: free/busy, contact lookup, ask, and, once the owner turns them on, list, share a file, a message excerpt, or a photo, and deliver into the Inbox) over MCP's Streamable HTTP on 127.0.0.1 (`GatewayServer`, Network.framework), with its own OAuth 2.1 authorization server (`GatewayAuthorization`: metadata, dynamic registration, PKCE S256, rotating refresh tokens, the owner's sign-in window). Plain code decides: standing grants per caller (`GatewayGrant`), the owner's cards (`GatewayDesk`: never the caller's words, deduplicated, bounded), and the disclosure ledger (`DisclosureLedger`: facts, units, budgets, and risk flags, never content). Its public address is the Tsukumo relay's client (`RelayConnection`: one outbound WebSocket, this Mac's P-256 key in the Keychain or Secure Enclave, relayed requests into the same `GatewayServer.respond(to:via:)`; the wire format alone in `RelayEnvelope`). `KemoSabeGateway` puts it together for an app. `GatewayTestAdapter` is a test-only executable for the independent attack suite. |
| `TsukumoSystemOne` | Decisions with per-kind thresholds and abstention. `SystemOne.decide` asks the local provider first (Laya, with the owner's personal layer), then hosted services in order, and each hosted call passes the policy first; each provider is raced against the decision's deadline. `SystemOneAPIProvider` speaks the System One API for Cloudflare Clef-flash and Clef (Workers AI's envelope), Jev, or a custom endpoint, and `SystemOneSettings` keeps them in the order they're asked, each agreed to for its host. `DecisionJournal` never holds the request's words. `SystemOne.route` picks the bot for an untagged message, falling back to the bot last spoken to. `SystemOneContextChooser` is `selectContext`. |
| `TsukumoEngines` | One `Engine` protocol that streams a turn: text, tool calls and results, approvals, and the reply. `APIEngine` speaks Claude's Messages API and OpenAI-compatible chat/completions, with keys kept in the Keychain. `OnDeviceEngine` runs Apple's on-device model (KemoSabe the bot). `CodingAgentEngine` (macOS) runs a turn on the owner's own coding CLI (`ClaudeCodeBackend`, `CodexBackend`, `ACPBackend`, found by `CodingAgentCatalog`), applies the access gate before asking the owner, and continues the chat's session. Every engine gets `read_reference` and `ask_kemosabe` through `TurnTools`. |
| `TsukumoSync` | `SyncEngine` syncs labeled items through a `CloudDatabase`, checking each against the policy for iCloud. Device only, Secret, KemoSabe's answers, and personal-source items never leave. `InMemoryCloudDatabase` is for tests. `CKCloudDatabase` is the CloudKit adapter. `LibraryMapping` and `LibrarySyncController` keep bots, chats, the default model, and connections (never keys) in step between Mac and iPhone: chats merge by message, deletes are tombstones, Device only chats and KemoSabe's shared answers never leave, and the status line says why sync is off. `CloudCapability` turns it on only in a build signed with the iCloud capability. |
| `TsukumoVoice` | Listening and speaking, always the best the device can run, with no model menus (the old KemoSabe app's evaluated stack). `VoiceHub` holds the two pinned downloads (`VoiceModelStore`: Whisper large-v3-turbo 4-bit and Kokoro-82M, checked file by file against size and SHA-256, after one consent), the owner's settings (spoken replies, pace), Settings' status lines, a turn of listening (`VoiceListener`: Apple's on-device recognizer for the live words, `EndOfSpeech` to end a tap when you stop talking, then Whisper's reading of the same audio when it can run, by `WhisperTranscription`'s rules), and a reply spoken in the bot's voice while it streams in (`ReplySpeech`, `SpeechQueue`, the Apple voice taking over if Kokoro fails). Each bot's voice is one of Kokoro's nine (`KokoroVoices.voice(for:)`), with Apple's closest voice standing in. `NeuralVoiceRuntime` is what MLXVoice fills. `ScriptedSpeechCapture` stands in for the microphone in tests and pictures. |
| `TsukumoUI` | The chat as on the website demo, at iPhone sizes or at Mac sizes with `ChatDensity.compact` (`ChatSession`, `ChatScreen`, KemoSabe's card with its consent and share cards, the composer with bot chips and `@name`), KemoSabe in its look and mood (`KemoSabeFigure`, `KemoSabeFace`, `TwoTonePainter`; the cloud in its palette is `CompanionArt`), the services' marks (`ServiceMarkView`) and the seam for a service's own panel (`ServiceBotPanelProvider`), the bots' settings (`BotSettingsSheet`: `KemoSabeEditor`, KemoSabe's palette grid and voice, or `ServiceBotEditor`, a service bot's model, voice, context, and permissions; a bot's voice is `VoicePicker`; the composer's microphone is `ComposerMicButton` and `ListeningStrip`, and `ChatSession.say` sends what was said and speaks the reply), the first run (`OnboardingFlow` over an app's `OnboardingHost`), the account (`AccountStore`, Sign in with Apple, `AccountSummary` with its sign-in hero or the name, initials, and sync's pill, and `SyncFacts`), API connections as both apps keep them (`ConnectionRecord`, `ModelCatalog`), Activity (`ActivityFeed`), and `DemoFixture`, which plays the website demo through the real Gate. The kit fills the chat's seams through `EngineRunner`, `GateAnswerer`, and `SystemOneRouter`. |
| `TsukumoMuse` | Tsukumo's Dock as a Muse gadget (macOS), so Meta's Muse can call Tsukumo as a caller of the KemoSabe gateway, which must ask KemoSabe. A Swift port of Meta's Apache-2.0 Muse Gadget SDK on CryptoKit and CoreBluetooth ([MUSE-NOTICE.md](MUSE-NOTICE.md)): the identity (`homelink-xxxxxx`, `MuseGadgetXXXXXX`), community pairing v5 (P-256, HKDF, AES-GCM, `confirm_app`) over a GATT peripheral that advertises only while pairing is open, the device API (VMs, token rotation), the Noise XX link (`/v1/noise`, `/link-control`, `/chat/stream`) with its reconnect loop, and `MuseGadget` for Settings. Muse's commands go through `MuseCommandHandler`; `TsukumoMuseCommands` offers only Tsukumo's own (`kemosabe.ask`, `kemosabe.free_busy`, `kemosabe.contact_lookup`, `bots.list`, `bot.ask`, `device.health`), never a shell or files, through `MuseTsukumo` (TsukumoDock's `DockMuseBridge`: `kemosabe.*` through `GatewayTools.call` with Muse as its own caller, a bot's reply recorded in the gateway's ledger). |
| `TsukumoUpdate` | Software Update for Tsukumo's Dock (macOS). `UpdateFeed` parses and checks `tsukumo.json` from zlichtman.com; `HTTPSUpdateTransport` fetches over HTTPS from exactly that host with redirects kept on it, size caps, and timeouts; `UpdateVerifier` checks the DMG's SHA-256, mounts it read-only on a private mount point, copies out the one Tsukumo.app, detaches it, and checks the copy (bundle ID, a newer build equal to the feed's, the feed's version, minimum macOS, this Mac's architecture, the team's Developer ID signature with `SecStaticCodeCheckValidity`, notarization); `UpdateInstaller`, under `UpdateLock`, checks it in full again before and after one atomic swap (no fallback) and starts the relaunch helper; `UpdateService` is what Settings shows (checks at launch and every six hours, Download, Install and Relaunch, a build this Mac can't run remembered, never in Debug, test, demo, or capture runs). Foundation, CryptoKit, and Security only. |
| `TsukumoClaude` | The Claude bot (macOS): an always-available agent on the owner's own Claude. `ClaudeBot` keeps its tasks (`ClaudeTask`: a goal, instructions, a `ClaudeSchedule`, a status, and runs with transcripts, results, and files) in `claude-bot.json`, runs a bounded number at once on `ClaudeEngineSelection`'s choice (Claude Code through `ClaudeCodeBackend` first, else the API key through `APIEngine`), restarts interrupted ones on launch, sends files to the gateway's Inbox, keeps results as artifacts it reads back by reference, and asks KemoSabe only through the gateway's typed tools as its own caller (`ClaudeKemoSabe`). `ClaudePanel` is its panel, for the dock through TsukumoUI's `ServiceBotPanelProvider` |
| `TsukumoDock` | The Mac's side dock (macOS), the Tsukumo Mac app's one face. `BotDock` is its model: the lineup (KemoSabe first, then each connected service's bot, from `connections`), one `ChatSession` per bot that chats plus Together, each tile's state (thinking, talking, working, needs you, done, asleep), KemoSabe's questions waiting on the owner (and the gateway's cards, `DockCallerCards.swift`), each service's callers, activity, and Revoke (`DockBotPanel`), callouts, and chirps from Calendar and Reminders. `BotDockController` puts the side dock on screen, always (a Liquid Glass shelf beside the Dock that tucks to a sliver, KemoSabe and the services' marks, a Settings tile and Together, magnification, styles, a bubble with a bot's chat or its panel; `setHidden` puts it away for now). `BotDockStore.migrateToLineup` moves an older file's custom bots once. `BotDockSettingsView` (`DockSettingsPage.swift`) is the app's Settings, Dock: a live preview of the shelf, style tiles, the dock's color, drawn choices, and a screen to tap for its position. Clicking a bot talks to it (`DockTalkGesture`, `BotDock.talk`, the listening ring and bubble), and `DockPushToTalk` is ⌃⌥D. `BotDock.standard` runs chats on TsukumoKit's engines and Gate; `BotDock.demo` plays the website demo. |

## Building

From this folder:

```sh
swift build --scratch-path /tmp/tsukumokit-build
```

Pass a scratch path outside iCloud Drive to keep build products out of it. `swift build --package-path MLXVoice --scratch-path /tmp/tsukumo-mlxvoice-build` builds the MLX package (it fetches MLX Swift and the Hugging Face packages the first time); the real models run in the Mac app's DEBUG `--voice-check` (DEVELOPMENT.md). There's no test suite (October 8, 2026); the apps that use these modules are in `apps/` (see DEVELOPMENT.md).
